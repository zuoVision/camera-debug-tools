# Camera Debug Studio 真实设备验收清单

每次发布至少选择一块可用开发板完成冒烟测试；涉及 Transport、终端或解析器修改时，Qualcomm 和 BMC 均需执行。
每项记录为 `PASS`、`FAIL`或 `BLOCKED`，并在 [发布验收记录](发布验收记录.md)
中附上证据或阻塞原因；未连接真实设备时不得记为通过。

## 通用准备

- 记录工具版本、操作系统、Profile、板端版本和执行人。
- 确认服务默认只监听 `127.0.0.1`；局域网验证必须设置访问令牌。
- 确认 `/api/config`、诊断摘要和服务日志中不存在 SSH 密码。

## Qualcomm / BMC（分别执行）

- 使用 SSH 私钥连接，运行 `hostname`，确认持续终端的目录与环境变量可保持。
- 使用测试密码账号连接，刷新页面后确认密码状态显示为“已配置”，且接口不返回密码。
- 断开网络后确认指标显示采集失败和连续失败次数；恢复网络并执行“重试失败项”。
- 检查 Link Lock、Video Lock、FPS 的原始输出、解析值、拓扑颜色及数据过期状态。
- 运行一个成功测试、一个预期失败测试和一个超时测试，检查退出码、状态和日志。
- 停止长任务，确认板端不存在残留 SSH、测试或子进程。
- 切换至另一个 Profile，确认旧终端断开、监控状态清空，新终端连接正确目标。
- 导出 JSON 和 Markdown 诊断报告，确认内容完整且已脱敏。

## Profile 特定检查

- Qualcomm：确认板端存在 `i2cdbgr`，命令的 bus/device/register 语法与当前镜像一致。
- BMC：确认板端存在 `csi`，`controller` 和 `channel` 与实际接线一致。
- 逐项检查拓扑中的指标绑定；未配置的指标会显示 `UNKNOWN`，需按项目实际命令补齐或确认为预期。

## 长稳验证

- 先执行 `python3 scripts/soak_test.py --report soak-local.json`，保存 Local 基线报告。
- 连续运行至少 8 小时，期间周期性记录进程内存、线程数和子进程数。
- 确认慢指标不会阻塞其他指标，同一指标不会重入，并发任务超过上限时得到明确提示。
- 验证结束后记录遗留问题、日志和诊断报告，随发布说明归档。
