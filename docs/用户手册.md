# Camera Debug Studio 工具介绍、操作与配置手册

## 1. 工具简介

Camera Debug Studio 是一款面向相机开发、Bring-up、问题定位和稳定性测试的通用调试工具。

工具通过 SSH 连接开发板，在远端执行平台命令，然后将命令输出转换成终端日志、监控状态或测试结果。平台差异全部放在 JSON 配置中，程序本身不绑定 Qualcomm、BMC 或某一种 I²C 工具。

主要功能：

- SSH 密码或私钥认证
- 远程命令执行、实时 stdout/stderr 和停止命令
- Link Lock、Video Lock、FPS、Ping 等状态监控
- 自定义 I²C 寄存器查询命令
- 正则解析、原始值映射和状态着色
- 测试脚本参数化运行、日志查看和停止任务
- Local、Qualcomm、BMC 等平台配置切换
- 网页内编辑、校验和保存完整 JSON 配置

## 2. 设计架构

```text
Web 操作界面
    ↓
统一命令/监控/测试模块
    ↓
SSH 或 Local Transport
    ↓
平台命令模板
    ↓
i2cdbgr / csi i2c / shell / 项目脚本
    ↓
正则或数值解析器
    ↓
状态卡片与测试结果
```

例如，同一个 Link Lock 指标可以在不同平台使用不同命令：

```text
Qualcomm: i2cdbgr r 1 0x52 0x0013
BMC:      csi i2c 1 1 0x52 0x0
```

后端不关心命令具体写法，只负责变量替换、远端执行和结果解析。

## 3. 运行环境

- Python 3.9 或更高版本
- macOS、Linux，或安装了 Python/OpenSSH 的 Windows
- SSH 场景需要系统存在 `ssh` 命令
- 浏览器支持 JavaScript

程序不依赖第三方 Python 包。

## 4. 启动工具

进入项目目录：

```bash
cd camera_debug_tools
```

启动：

```bash
python3 camera_debug.py
```

默认访问地址：

```text
http://127.0.0.1:8765/
```

不要直接双击 `web/index.html`。`file://` 页面无法访问后端接口。

如果提示服务已经运行，直接访问上述地址即可。

指定配置启动：

```bash
python3 camera_debug.py --config configs/qualcomm-example.json
```

指定端口：

```bash
python3 camera_debug.py --port 9000
```

允许局域网其他电脑访问：

```bash
python3 camera_debug.py --host 0.0.0.0
```

其他电脑访问：

```text
http://运行工具的电脑IP:8765/
```

工具允许执行远程命令，局域网模式只应在可信网络使用。

## 5. 页面功能

### 5.1 监控看板

监控看板按照配置的周期自动执行监控命令，并把输出转换成状态卡片。

典型指标：

- Link Lock
- Video Lock
- FPS
- Camera Host 在线状态
- 温度、电压、错误计数

处理流程：

```text
执行命令 → 获取原始输出 → 正则提取 → map 映射 → 看板显示
```

### 5.2 命令终端

1. 在输入框中填写命令。
2. 点击“执行”或按 Enter。
3. stdout 正常显示，stderr 使用错误颜色显示。
4. 长时间运行的命令可点击“停止命令”。

终端命令通过当前 `target.transport` 执行：

- `ssh`：在远程开发板执行
- `local`：在运行 Camera Debug Studio 的电脑执行

终端顶部会显示当前目标，例如：

```text
root@192.168.1.10
```

执行 `hostname`、`pwd` 或 `uname -a` 可以确认当前是否为远端环境。

### 5.3 测试中心

测试中心将当前平台配置文件 `tests` 数组中的任务显示为下拉选项。选择测试项后，页面会同时显示测试说明、参数和最终执行脚本。

操作方式：

1. 从“测试项”下拉框选择测试。
2. 阅读测试说明。
3. 填写测试参数。
4. 在“执行脚本”区域确认参数替换后的完整命令。
5. 点击“运行测试”。
6. 查看实时输出。
7. 需要提前结束时点击“停止”。

测试命令同样通过当前 SSH/Local Transport 执行。

如果当前平台的 `tests` 是空数组，页面会显示“当前平台没有配置测试项”。需要进入“平台配置”，在 JSON 编辑器的 `tests` 数组中添加任务并保存。

### 5.4 平台配置

平台配置页面由两部分组成。

SSH 连接区域用于修改：

- Transport 类型
- 开发板地址
- SSH 端口
- 用户名
- 密码
- 私钥路径
- 连接超时

平台适配配置区域用于：

- 切换 Local Demo、Qualcomm、BMC 等配置文件
- 编辑完整 JSON
- 修改 I²C 命令和寄存器
- 修改解析规则
- 修改测试脚本
- 保存并立即生效

## 6. SSH 连接

### 6.1 密码认证

1. 连接方式选择“SSH（远程开发板）”。
2. 填写主机、端口、用户名和密码。
3. 点击“保存并测试 SSH”。
4. 显示连接成功后进入命令终端。

密码不会写入 JSON，也不会出现在配置预览中。密码只保存在当前后端进程内存，程序退出后自动清除。

### 6.2 私钥认证

填写私钥路径，例如：

```text
~/.ssh/id_ed25519
```

如果私钥已通过系统 SSH Agent 管理，可以留空。

### 6.3 验证远程执行

在命令终端执行：

```bash
hostname
```

如果输出开发板主机名，说明终端正在远端执行。

如果终端显示 `Local`，说明当前配置仍为：

```json
"transport": "local"
```

## 7. 配置文件结构

配置文件位于 `configs/`：

```text
configs/
├── demo-local.json
├── qualcomm-example.json
└── bmc-example.json
```

顶层结构：

```json
{
  "project": {},
  "target": {},
  "variables": {},
  "monitoring": {"metrics": []},
  "tests": []
}
```

### 7.1 project

```json
"project": {
  "name": "BMC Camera Board",
  "platform": "BMC"
}
```

- `name`：项目或开发板名称
- `platform`：平台名称

### 7.2 target

SSH 示例：

```json
"target": {
  "transport": "ssh",
  "host": "192.168.1.20",
  "port": 22,
  "user": "root",
  "identityFile": "",
  "connectTimeout": 8,
  "sshOptions": [
    "StrictHostKeyChecking=accept-new"
  ]
}
```

Local 示例：

```json
"target": {
  "transport": "local",
  "localShell": "/bin/sh"
}
```

密码不会保存在 `target` 中。

### 7.3 variables

用于保存项目公共参数：

```json
"variables": {
  "controller": 1,
  "channel": 1,
  "device": "0x52",
  "link_reg": "0x0",
  "video_reg": "0x1"
}
```

在命令中使用 `{变量名}`：

```json
"command": "csi i2c {controller} {channel} {device} {link_reg}"
```

实际执行：

```bash
csi i2c 1 1 0x52 0x0
```

## 8. 监控指标配置

完整示例：

```json
{
  "id": "link_lock",
  "name": "Link Lock",
  "group": "Camera 0",
  "command": "csi i2c {controller} {channel} {device} {link_reg}",
  "interval": 2,
  "timeout": 5,
  "parser": {
    "type": "regex",
    "pattern": "(?:value|data)[=: ]+(0x[0-9a-fA-F]+|\\d+)",
    "group": 1,
    "map": {
      "0x1": "LOCKED",
      "1": "LOCKED",
      "0x0": "UNLOCKED",
      "0": "UNLOCKED"
    }
  },
  "display": {
    "kind": "status",
    "goodValues": ["LOCKED"]
  }
}
```

字段说明：

| 字段 | 含义 |
|---|---|
| `id` | 指标唯一标识，不能重复 |
| `name` | 卡片名称 |
| `group` | 相机、链路或模块分组 |
| `command` | 周期执行的远端命令 |
| `interval` | 采集周期，单位秒 |
| `timeout` | 单次命令超时，单位秒 |
| `enabled` | 是否启用，默认 `true` |
| `parser` | 输出解析规则 |
| `display` | 展示方式和正常状态 |

### 8.1 regex 解析器

```json
"parser": {
  "type": "regex",
  "pattern": "FPS=([0-9.]+)",
  "group": 1
}
```

对于输出：

```text
FPS=29.97
```

提取结果是 `29.97`。

### 8.2 map 映射

```json
"map": {
  "0x01": "LOCKED",
  "0x00": "UNLOCKED"
}
```

把不直观的寄存器原始值映射成人类可读状态。

### 8.3 display

状态类：

```json
"display": {
  "kind": "status",
  "goodValues": ["LOCKED"]
}
```

`LOCKED` 会显示为正常颜色，其他值或解析错误显示异常颜色。

数值类：

```json
"display": {
  "kind": "number",
  "unit": "fps",
  "warnBelow": 25
}
```

低于 25 fps 时显示警告颜色。

## 9. I²C 配置示例

### 9.1 Qualcomm i2cdbgr

命令：

```bash
i2cdbgr r 1 0x52 0x0013
```

配置：

```json
{
  "id": "link_lock",
  "name": "Link Lock",
  "command": "i2cdbgr r {bus} {device} {link_reg}",
  "interval": 2,
  "parser": {
    "type": "regex",
    "pattern": "(?:0x)?([0-9a-fA-F]+)\\s*$",
    "group": 1,
    "map": {
      "1": "LOCKED",
      "0": "UNLOCKED"
    }
  },
  "display": {
    "kind": "status",
    "goodValues": ["LOCKED"]
  }
}
```

### 9.2 BMC csi i2c

命令：

```bash
csi i2c 1 1 0x52 0x0
```

配置：

```json
{
  "id": "link_lock",
  "name": "Link Lock",
  "command": "csi i2c {controller} {channel} {device} {link_reg}",
  "interval": 2,
  "parser": {
    "type": "regex",
    "pattern": "(?:value|data)[=: ]+(0x[0-9a-fA-F]+|\\d+)",
    "group": 1,
    "map": {
      "0x1": "LOCKED",
      "1": "LOCKED",
      "0x0": "UNLOCKED",
      "0": "UNLOCKED"
    }
  },
  "display": {
    "kind": "status",
    "goodValues": ["LOCKED"]
  }
}
```

接入新命令时，应先在命令终端执行一次，记录真实输出，再编写 `pattern` 和 `map`。

## 10. Ping 监控示例

```json
{
  "id": "camera_ping",
  "name": "Camera Host",
  "group": "192.168.31.3",
  "command": "ping -c 1 192.168.31.3",
  "interval": 3,
  "timeout": 3,
  "parser": {
    "type": "regex",
    "pattern": "(1 packets received|1 received)",
    "group": 1,
    "map": {
      "1 packets received": "ONLINE",
      "1 received": "ONLINE"
    }
  },
  "display": {
    "kind": "status",
    "goodValues": ["ONLINE"]
  }
}
```

使用 `ping -c 1` 是为了让单次采集能够结束。直接使用无限运行的 `ping` 会等待到超时。

## 11. 测试任务配置

```json
{
  "id": "camera_test",
  "name": "相机测试脚本",
  "description": "远端运行项目测试脚本",
  "command": "/opt/camera/tests/run.sh --camera {camera}",
  "params": [
    {
      "name": "camera",
      "label": "Camera ID",
      "type": "number",
      "default": 0
    }
  ]
}
```

参数字段：

| 字段 | 含义 |
|---|---|
| `name` | 模板变量名 |
| `label` | 页面显示名称 |
| `type` | `number` 或文本 |
| `default` | 默认值 |
| `pattern` | 可选的输入校验正则 |
| `choices` | 可选值列表 |

配置保存后，测试项会自动出现在测试中心下拉框中。例如：

```json
"tests": [
  {
    "id": "camera_test",
    "name": "相机测试脚本",
    "description": "远端运行项目测试脚本",
    "command": "/opt/camera/tests/run.sh --camera {camera}",
    "params": [
      {
        "name": "camera",
        "label": "Camera ID",
        "type": "number",
        "default": 0
      }
    ]
  }
]
```

当 Camera ID 输入 `2` 时，脚本预览显示：

```bash
/opt/camera/tests/run.sh --camera 2
```

## 12. 添加新平台

1. 复制最接近的平台配置。
2. 修改 `project.name` 和 `project.platform`。
3. 修改 `target` SSH 默认值。
4. 在 `variables` 中定义总线、设备地址和寄存器。
5. 修改每个指标的 `command`。
6. 根据真实输出修改 `parser.pattern`。
7. 使用 `map` 将寄存器值转换成状态。
8. 保存配置并观察监控卡片。

新配置文件放入 `configs/` 后，刷新页面即可出现在平台选择器中。

## 13. 常见问题

### 13.1 页面空白或接口不可用

错误方式：

```text
file:///.../web/index.html
```

正确方式：

```text
http://127.0.0.1:8765/
```

### 13.2 Address already in use

说明服务已经运行。直接访问现有地址，无需再次启动。

也可以换端口：

```bash
python3 camera_debug.py --port 9000
```

### 13.3 终端命令在本机执行

检查：

```json
"transport": "ssh"
```

如果是 `local`，终端必然在本机执行。重新保存并测试 SSH 后再进入终端。

### 13.4 SSH 测试失败

检查：

- IP 地址是否可达
- SSH 端口是否正确
- 用户名和密码是否正确
- 开发板是否允许密码认证
- 私钥权限是否正确
- 首次连接是否能接受 Host Key

可以先在系统终端验证：

```bash
ssh -p 22 root@192.168.1.10
```

### 13.5 看板显示 `--`

通常表示：

- 命令执行失败
- SSH 连接失败
- 命令超时
- 正则没有匹配真实输出

先在命令终端执行监控命令，复制原始输出，然后调整 `parser.pattern`。

### 13.6 修改配置后没有变化

确认已经点击“保存配置”，而不只是编辑文本。必要时点击“放弃修改/重新加载”确认磁盘中的当前配置。

## 14. 安全说明

- SSH 密码只保存在当前进程内存，不写入配置。
- 不要将工具直接暴露到公网。
- 局域网共享时应限制可信设备访问。
- 远程命令拥有目标 SSH 用户的权限。
- 不要在配置中写入密码、Token 或其他密钥。
- 建议优先使用权限受限的开发账号和 SSH 密钥。
