# Camera Debug Studio 工具介绍、操作与配置手册

## 1. 工具简介

Camera Debug Studio 是一款面向相机开发、Bring-up、问题定位和稳定性测试的通用调试工具。

工具通过 SSH 连接开发板，在远端执行平台命令，然后将命令输出转换成终端日志、监控状态或测试结果。平台差异全部放在 JSON 配置中，程序本身不绑定 Qualcomm、BMC 或某一种 I²C 工具。

主要功能：

- SSH 密码或私钥认证
- 远程命令执行、实时 stdout/stderr 和停止命令
- Link Lock、Video Lock、FPS、Ping 等状态监控
- 自定义 I²C 寄存器查询命令
- 正则解析、原始值映射和状态着色
- 测试脚本参数化运行、日志查看和停止任务
- Local、Qualcomm、BMC 等平台配置切换
- 网页内编辑、校验和保存完整 JSON 配置

## 2. 设计架构

```text
Web 操作界面
    ↓
统一命令/监控/测试模块
    ↓
SSH 或 Local Transport
    ↓
平台命令模板
    ↓
i2cdbgr / csi i2c / shell / 项目脚本
    ↓
正则或数值解析器
    ↓
状态卡片与测试结果
```

例如，同一个 Link Lock 指标可以在不同平台使用不同命令：

```text
Qualcomm: i2cdbgr r 1 0x52 0x0013
BMC:      csi i2c 1 1 0x52 0x0
```

后端不关心命令具体写法，只负责变量替换、远端执行和结果解析。

## 3. 运行环境

- Python 3.9 或更高版本
- macOS、Linux，或安装了 Python/OpenSSH 的 Windows
- SSH 场景需要系统存在 `ssh` 命令
- 浏览器支持 JavaScript

程序不依赖第三方 Python 包。

## 4. 启动工具

进入项目目录：

```bash
cd camera_debug_tools
```

启动：

```bash
python3 camera_debug.py
```

默认访问地址：

```text
http://127.0.0.1:8765/
```

不要直接双击 `web/index.html`。`file://` 页面无法访问后端接口。

如果提示服务已经运行，直接访问上述地址即可。

指定配置启动：

```bash
python3 camera_debug.py --config configs/profiles/qualcomm
```

指定端口：

```bash
python3 camera_debug.py --port 9000
```

允许局域网其他电脑访问：

```bash
python3 camera_debug.py --host 0.0.0.0 --access-token '请替换为足够长的随机值'
```

其他电脑访问：

```text
http://运行工具的电脑IP:8765/?token=访问令牌
```

浏览器会将令牌保存在本地。也可在启动前设置 `CAMERA_DEBUG_ACCESS_TOKEN`
环境变量。工具允许执行远程命令，局域网模式只应在可信网络使用。

## 5. 页面功能

### 5.1 监控看板

监控看板按照配置的周期自动执行监控命令，并把输出转换成状态卡片。

看板支持暂停/恢复全部监控、按指标分组立即刷新，以及只重试当前分组中的失败指标。
刷新按钮会短暂锁定以避免连续点击形成刷新风暴；后端仍保证同一个指标不会并发重入。

典型指标：

- Link Lock
- Video Lock
- FPS
- Camera Host 在线状态
- 温度、电压、错误计数

处理流程：

```text
执行命令 → 获取原始输出 → 正则提取 → map 映射 → 看板显示
```

### 5.2 命令终端

1. 点击黑色终端区域，使终端获得键盘焦点。
2. 直接在远端 Shell 提示符后输入命令，不再使用单独的网页输入行。
3. 按 Enter 执行；Tab、退格、方向键等按键会原样发送给远端 PTY。
4. 按 ↑ / ↓ 使用远端 Shell 自身的历史命令功能。
5. 长时间运行的命令可按 Ctrl+C，或点击“停止命令”。

命令终端通过 WebSocket 连接后端 PTY，并保持同一个 SSH/Login Shell 会话。因此工作目录、环境变量和 Shell 上下文会持续保留，例如先执行 `cd /tmp`，再执行 `pwd` 会得到 `/tmp`。切换平台、修改 SSH 连接或刷新网页时，原会话会关闭并重新建立。

终端区域会自动占满浏览器剩余可用高度。调整窗口大小或浏览器缩放比例时，页面会重新计算终端列数和行数，并同步到远端 PTY，无需手动刷新。

在 Windows 上，工具使用系统 OpenSSH 或持久的 `cmd.exe`/PowerShell 管道代替 POSIX PTY，不再显示“PTY 终端当前支持 macOS 和 Linux”。远程 SSH 会话仍可保持目录和 Shell 状态；Windows 本地模式不支持终端尺寸同步，部分全屏交互程序的显示能力弱于 macOS/Linux。若中文输出乱码，可在 `target.json` 中增加 `"terminalEncoding": "gbk"` 或目标实际使用的编码。

终端命令通过当前 `target.transport` 执行：

- `ssh`：在远程开发板执行
- `local`：在运行 Camera Debug Studio 的电脑执行

终端顶部会显示当前目标，例如：

```text
root@192.168.1.10
```

执行 `hostname`、`pwd` 或 `uname -a` 可以确认当前是否为远端环境。

### 5.3 测试中心

测试中心将当前平台配置文件 `tests` 数组中的任务显示为下拉选项。选择测试项后，页面会同时显示测试说明、参数和最终执行脚本。

操作方式：

1. 从“测试项”下拉框选择测试。
2. 阅读测试说明。
3. 填写测试参数。
4. 在“执行脚本”区域确认参数替换后的完整命令。
5. 点击“运行测试”。
6. 查看实时输出。
7. 需要提前结束时点击“停止”。

测试命令同样通过当前 SSH/Local Transport 执行。

测试中心还提供独立的 **Pytest 项目** 区域。将 Pytest 项目放入工具根目录的 `test/`，然后点击“刷新用例”。工具会收集完整 node ID（包括测试类和参数化用例），选择后在运行 Camera Debug Studio 的电脑上执行：

```bash
python -m pytest -v --color=no test/test_example.py::test_name
```

Pytest 用例不通过 SSH Transport。如果页面提示未安装 Pytest，请在启动工具所使用的 Python 环境执行：

```bash
python -m pip install pytest
```

工具优先使用 `test/.venv` 或项目根目录 `.venv` 的 Python。也可以在启动前设置 `CAMERA_DEBUG_PYTEST_PYTHON`，指定已有 Pytest 环境的 Python 路径。

如果当前平台的 `tests` 是空数组，页面会显示“当前平台没有配置测试项”。需要进入“平台配置”，在 JSON 编辑器的 `tests` 数组中添加任务并保存。

### 5.4 平台配置

平台配置页面由两部分组成。

SSH 连接区域用于修改：

- Transport 类型
- 开发板地址
- SSH 端口
- 用户名
- 密码
- 私钥路径
- 连接超时

平台适配配置区域用于：

- 切换 Local Demo、Qualcomm、BMC 等配置文件
- 编辑完整 JSON
- 修改 I²C 命令和寄存器
- 修改解析规则
- 修改测试脚本
- 保存并立即生效

编辑 JSON 时页面会跟踪未保存修改，离开页面或切换平台前给出提醒。保存前会先执行后端
校验并展示修改摘要；校验错误可定位到对应字段。使用“复制 Profile”可从当前平台创建新
配置，密码和 `target.local.json` 不会被复制。

### 5.5 诊断信息与诊断会话

“诊断信息”页面展示服务版本、运行时间、监控状态、最近错误和任务历史。复现问题前可输入
名称并开始诊断会话；工具会保存指标快照，并按时间记录任务、指标采集和 Profile 变化。
会话最多保留最近 500 条事件，结束后可导出脱敏 JSON 或 Markdown 报告。报告不会包含
SSH 密码、访问令牌或私钥内容。

任务历史可以按“进行中、成功、失败/超时、已停止”筛选。清空操作只删除已结束任务，
不会停止或删除正在运行的任务。

## 6. SSH 连接

### 6.1 密码认证

1. 连接方式选择“SSH（远程开发板）”。
2. 填写主机、端口、用户名和密码。
3. 点击“保存并测试 SSH”。
4. 显示连接成功后进入命令终端。

密码会明文写入当前平台、且被 Git 忽略的 `target.local.json`，重新启动程序或切换回该平台后仍可使用。留空并保存连接会清除已有密码。

### 6.2 私钥认证

填写私钥路径，例如：

```text
~/.ssh/id_ed25519
```

如果私钥已通过系统 SSH Agent 管理，可以留空。

### 6.3 验证远程执行

在命令终端执行：

```bash
hostname
```

如果输出开发板主机名，说明终端正在远端执行。

如果终端显示 `Local`，说明当前配置仍为：

```json
"transport": "local"
```

## 7. 配置文件结构

平台配置位于 `configs/profiles/`，每个平台的功能模块使用独立文件：

```text
configs/profiles/
├── demo-local/
│   ├── project.json
│   ├── target.json
│   ├── variables.json
│   ├── monitoring.json
│   ├── topology.json
│   └── tests.json
├── qualcomm/
└── bmc/
```

模块职责：

| 文件 | 内容 |
|---|---|
| `project.json` | 项目名称和平台信息 |
| `target.json` | SSH/Local 连接参数 |
| `variables.json` | 总线、设备地址和寄存器等公共变量 |
| `monitoring.json` | 监控命令、解析器和展示规则 |
| `topology.json` | 节点、连接和指标绑定 |
| `tests.json` | 测试脚本和参数 |

后端读取这些文件后会在内存中合并成统一结构：

```json
{
  "project": {},
  "target": {},
  "variables": {},
  "monitoring": {"metrics": []},
  "tests": []
}
```

### 7.1 project

```json
"project": {
  "name": "BMC Camera Board",
  "platform": "BMC"
}
```

- `name`：项目或开发板名称
- `platform`：平台名称

### 7.2 target

SSH 示例：

```json
"target": {
  "transport": "ssh",
  "host": "192.168.1.20",
  "port": 22,
  "user": "root",
  "identityFile": "",
  "connectTimeout": 8,
  "sshOptions": [
    "StrictHostKeyChecking=accept-new"
  ]
}
```

Local 示例：

```json
"target": {
  "transport": "local",
  "localShell": "/bin/sh"
}
```

`target` 支持明文密码字段：

```json
"password": "your-password"
```

建议仅在受控调试环境使用，并避免把真实密码提交到 Git。

### 7.3 variables

用于保存项目公共参数：

```json
"variables": {
  "controller": 1,
  "channel": 1,
  "device": "0x52",
  "link_reg": "0x0",
  "video_reg": "0x1"
}
```

在命令中使用 `{变量名}`：

```json
"command": "csi i2c {controller} {channel} {device} {link_reg}"
```

实际执行：

```bash
csi i2c 1 1 0x52 0x0
```

## 8. 监控指标配置

推荐在“监控看板 → 详细指标 → 编辑指标”中完成日常配置。编辑模式左侧选择指标，右侧可编辑指标 ID、名称、分组、采集命令、周期、超时、解析类型、正则表达式、结果映射、展示类型、单位、告警下限和正常值。支持新增、删除、恢复当前指标、取消全部修改与保存生效。

结果映射采用每行一项的形式：

```text
1=LOCKED
0=UNLOCKED
```

修改指标 ID 时，编辑器会同步更新拓扑连接中的 `linkMetric` 和 `videoMetric` 引用；删除指标时会清除对应拓扑绑定。页面下方的 JSON 编辑器继续作为高级配置入口。

完整示例：

```json
{
  "id": "link_lock",
  "name": "Link Lock",
  "group": "Camera 0",
  "command": "csi i2c {controller} {channel} {device} {link_reg}",
  "interval": 2,
  "timeout": 5,
  "parser": {
    "type": "regex",
    "pattern": "(?:value|data)[=: ]+(0x[0-9a-fA-F]+|\\d+)",
    "group": 1,
    "map": {
      "0x1": "LOCKED",
      "1": "LOCKED",
      "0x0": "UNLOCKED",
      "0": "UNLOCKED"
    }
  },
  "display": {
    "kind": "status",
    "goodValues": ["LOCKED"]
  }
}
```

字段说明：

| 字段 | 含义 |
|---|---|
| `id` | 指标唯一标识，不能重复 |
| `name` | 卡片名称 |
| `group` | 相机、链路或模块分组 |
| `command` | 周期执行的远端命令 |
| `interval` | 采集周期，单位秒 |
| `timeout` | 单次命令超时，单位秒 |
| `enabled` | 是否启用，默认 `true` |
| `parser` | 输出解析规则 |
| `display` | 展示方式和正常状态 |

### 8.1 regex 解析器

```json
"parser": {
  "type": "regex",
  "pattern": "FPS=([0-9.]+)",
  "group": 1
}
```

对于输出：

```text
FPS=29.97
```

提取结果是 `29.97`。

### 8.2 bit 位解析

在正则或数值解析器提取寄存器原始值后，可以使用零起始的 `bit` 只保留指定 bit：

```json
"parser": {
  "type": "regex",
  "pattern": "\\[0x[0-9a-fA-F]+\\]\\s*=\\s*(0x[0-9a-fA-F]+)",
  "group": 1,
  "bit": 3,
  "map": {
    "0": "LOST",
    "1": "LOCKED"
  }
}
```

例如原始值为 `0xdb` 时，`bit: 3` 的结果是 `(0xdb >> 3) & 1 = 1`。`bit` 转换发生在 `map` 映射之前，支持十六进制（如 `0xdb`）和十进制输入。

### 8.3 map 映射

```json
"map": {
  "0x01": "LOCKED",
  "0x00": "UNLOCKED"
}
```

把不直观的寄存器原始值映射成人类可读状态。

### 8.4 display

状态类：

```json
"display": {
  "kind": "status",
  "goodValues": ["LOCKED"]
}
```

`LOCKED` 会显示为正常颜色，其他值或解析错误显示异常颜色。

数值类：

```json
"display": {
  "kind": "number",
  "unit": "fps",
  "warnBelow": 25
}
```

低于 25 fps 时显示警告颜色。

## 9. I²C 配置示例

### 动态拓扑图配置

监控看板可以通过 `topology` 描述 Camera、Deserializer、Serializer 和 SoC 之间的连接关系。拓扑结构不写死在前端，因此不同项目可以增删节点和链路。

#### 可视化编辑模式

1. 在监控看板点击“编辑拓扑”。
2. 修改“画布高度”，或点击“根据节点数自动调整”；画布宽度会随窗口自动适应。
3. 直接拖动图中的节点调整位置。
4. 在节点表单修改名称、类型、副标题、坐标、宽度和高度。也可以拖动节点右下角的蓝色手柄直接调整长宽，每个节点独立保存。
5. 点击“新增节点”创建 Camera、DES、Serializer、SoC 或普通设备。
6. 在连接表单选择起点、终点、Link 指标和 Video 指标。
7. 点击“新增连接”建立链路。
8. 可在连接列表或节点区域删除不需要的项目。
9. 点击“保存拓扑”写入当前平台配置；点击“取消”恢复磁盘配置。

进入编辑模式后，连接表单会自动选择当前节点作为起点，并选择另一个节点作为终点；编辑器刷新时会保留当前选择。少于两个节点时会禁用“新增连接”。删除节点会同时删除与该节点关联的连接。拓扑编辑模式中的操作在点击保存前不会写入配置文件。

```json
"topology": {
  "height": 720,
  "nodes": [
    {"id": "cam0", "type": "camera", "label": "CAM 0", "x": 10, "y": 20},
    {"id": "des0", "type": "deserializer", "label": "DES0", "subtitle": "MAX96712", "x": 50, "y": 50},
    {"id": "soc", "type": "soc", "label": "SoC", "x": 88, "y": 50}
  ],
  "edges": [
    {
      "from": "cam0",
      "to": "des0",
      "linkMetric": "cam0_link_lock",
      "videoMetric": "cam0_video_lock"
    },
    {
      "from": "des0",
      "to": "soc",
      "linkMetric": "des_soc_link",
      "videoMetric": "des_soc_video"
    }
  ]
}
```

节点字段：

| 字段 | 含义 |
|---|---|
| `id` | 节点唯一标识 |
| `type` | `camera`、`deserializer`、`serializer` 或 `soc` |
| `label` | 节点主标题 |
| `subtitle` | 芯片型号等副标题 |
| `x`、`y` | 节点在拓扑画布中的百分比坐标，范围 0–100 |

连接字段：

| 字段 | 含义 |
|---|---|
| `from`、`to` | 起点和终点节点 ID |
| `linkMetric` | 判断物理链路状态的监控指标 ID |
| `videoMetric` | 判断视频数据状态的监控指标 ID |

拓扑状态规则：

- 指标尚未采集：灰色虚线，显示 `WAITING`
- Link 为 `UNLOCKED`、`LOST`、`0`：红色断线和断点标记
- Link 为 `LOCKED`、`ONLINE`、`1`：绿色实线
- Link 和 Video 都 Lock：青色动态数据流
- DES/SoC 同时存在正常和断开链路：节点显示黄色 `DEGRADED`

`linkMetric` 和 `videoMetric` 必须与 `monitoring.metrics[].id` 对应。例如：

```json
{
  "id": "cam0_link_lock",
  "name": "CAM 0 Link Lock",
  "command": "csi i2c 1 1 0x52 0x1a",
  "parser": {
    "type": "regex",
    "pattern": "(0x[0-9a-fA-F]+)",
    "group": 1,
    "map": {
      "0x1": "LOCKED",
      "0x0": "UNLOCKED"
    }
  }
}
```

  },

    "kind": "status",

  }
}
```

      "1": "LOCKED",
      "0x0": "UNLOCKED",
      "0": "UNLOCKED"
    }
  },
  "display": {
    "kind": "status",
    "goodValues": ["LOCKED"]
  }
}
```

接入新命令时，应先在命令终端执行一次，记录真实输出，再编写 `pattern` 和 `map`。

## 10. Ping 监控示例

```json
{
  "id": "camera_ping",
  "name": "Camera Host",
  "group": "192.168.31.3",
  "command": "ping -c 1 192.168.31.3",
  "interval": 3,
  "timeout": 3,
  "parser": {
    "type": "regex",
    "pattern": "(1 packets received|1 received)",
    "group": 1,
    "map": {
      "1 packets received": "ONLINE",
      "1 received": "ONLINE"
    }
  },
  "display": {
    "kind": "status",
    "goodValues": ["ONLINE"]
  }
}
```

使用 `ping -c 1` 是为了让单次采集能够结束。直接使用无限运行的 `ping` 会等待到超时。

## 11. 测试任务配置

```json
{
  "id": "camera_test",
  "name": "相机测试脚本",
  "description": "远端运行项目测试脚本",
  "command": "/opt/camera/tests/run.sh --camera {camera}",
  "params": [
    {
      "name": "camera",
      "label": "Camera ID",
      "type": "number",
      "default": 0
    }
  ]
}
```

参数字段：

| 字段 | 含义 |
|---|---|
| `name` | 模板变量名 |
| `label` | 页面显示名称 |
| `type` | `number` 或文本 |
| `default` | 默认值 |
| `pattern` | 可选的输入校验正则 |
| `choices` | 可选值列表 |

配置保存后，测试项会自动出现在测试中心下拉框中。例如：

```json
"tests": [
  {
    "id": "camera_test",
    "name": "相机测试脚本",
    "description": "远端运行项目测试脚本",
    "command": "/opt/camera/tests/run.sh --camera {camera}",
    "params": [
      {
        "name": "camera",
        "label": "Camera ID",
        "type": "number",
        "default": 0
      }
    ]
  }
]
```

当 Camera ID 输入 `2` 时，脚本预览显示：

```bash
/opt/camera/tests/run.sh --camera 2
```

## 12. 添加新平台

1. 复制最接近的平台配置。
2. 修改 `project.name` 和 `project.platform`。
3. 修改 `target` SSH 默认值。
4. 在 `variables` 中定义总线、设备地址和寄存器。
5. 修改每个指标的 `command`。
6. 根据真实输出修改 `parser.pattern`。
7. 使用 `map` 将寄存器值转换成状态。
8. 保存配置并观察监控卡片。

新平台目录放入 `configs/profiles/` 后，刷新页面即可出现在平台选择器中。旧的单文件 JSON 仍可通过 `--config` 参数兼容读取，也可以使用迁移脚本拆分：

```bash
python3 scripts/split_profiles.py configs/old-platform.json
```

## 13. 常见问题

### 13.1 页面空白或接口不可用

错误方式：

```text
file:///.../web/index.html
```

正确方式：

```text
http://127.0.0.1:8765/
```

### 13.2 Address already in use

说明服务已经运行。直接访问现有地址，无需再次启动。

也可以换端口：

```bash
python3 camera_debug.py --port 9000
```

### 13.3 终端命令在本机执行

检查：

```json
"transport": "ssh"
```

如果是 `local`，终端必然在本机执行。重新保存并测试 SSH 后再进入终端。

### 13.4 SSH 测试失败

检查：

- IP 地址是否可达
- SSH 端口是否正确
- 用户名和密码是否正确
- 开发板是否允许密码认证
- 私钥权限是否正确
- 首次连接是否能接受 Host Key

可以先在系统终端验证：

```bash
ssh -p 22 root@192.168.1.10
```

### 13.5 看板显示 `--`

通常表示：

- 命令执行失败
- SSH 连接失败
- 命令超时
- 正则没有匹配真实输出

先在命令终端执行监控命令，复制原始输出，然后调整 `parser.pattern`。

### 13.6 修改配置后没有变化

确认已经点击“保存配置”，而不只是编辑文本。必要时点击“放弃修改/重新加载”确认磁盘中的当前配置。

## 14. 安全说明

- SSH 密码明文保存在当前平台的 `target.local.json`，该文件默认被 Git 忽略。
- 不要将工具直接暴露到公网。
- 局域网共享时必须设置访问令牌，并限制可信设备访问。
- 远程命令拥有目标 SSH 用户的权限。
- 不要把包含真实密码、Token 或其他密钥的配置提交到 Git。
- 建议优先使用权限受限的开发账号和 SSH 密钥。
